# HeroUI Pro 前端迁移

2026-11-20。本轮在本地完成组件迁移、视觉调整和验证；未执行远端发布。

## 组件与交互

依据 HeroUI MCP 文档使用 11 个 Pro 组件家族：Sidebar、DataGrid、ListView、ActionBar、EmptyState、KPI、KPIGroup、ItemCard、ItemCardGroup、InlineSelect、Segment。

- 桌面提醒与投递使用 DataGrid，空间不足时切换为 ListView。状态标签保持单行，操作列固定，已结束的投递仍可打开详情。
- 批量操作使用 ActionBar，桌面按内容区域居中，手机将数量与关闭、操作按钮分为两行，避开屏幕边缘和安全区域。
- Sidebar 提供桌面导航和手机抽屉。保留未保存修改确认、浏览器返回保护和导航后关闭抽屉。
- 概览指标使用 KPIGroup；未来七天、最近投递、投递节奏分别置于 Card，建立明确边界。名称与周期分行；零投递数据使用 EmptyState。
- 设置分类在 320px 完整展示，面板切换保留草稿。审计标识缩略展示，可打开详情或复制完整值。
- 表单覆盖登录、提醒编辑、连接、设备、安全、投递修正及列表筛选。单行控件统一 44px；桌面和触摸设备的标签与内容均为 14px，辅助说明 13px。
- 编辑器结束方式与次数／截止日期在空间足够时同行，窄屏按顺序换行。
- 结束方式使用 Pro Segment；为与相邻表单控件一致，外框使用原生 field-radius（12px），内选项使用原生 radius（8px），间距 4px；选中项无额外阴影。
- 设置分类沿用同一组内外圆角，在手机两行排列时保持边界一致。
- 保留原有业务 API、调度、修订冲突检测和保存期间草稿保护。

## 色彩与样式

以 HeroUI 默认蓝色的色相 `253.83` 为基准。浅色主色使用 `oklch(0.55 0.195 253.83)`，提高小号白色按钮文字的对比度（浏览器实测约 4.8:1）。背景恢复 HeroUI 默认的 `oklch(0.9702 0 0)`，卡片和弹层使用原生白色表面；表单使用 secondary 变体。成功、警告和错误使用原生语义颜色。

按两个 Skill 的原生外观、细微层次和避免重复阴影要求，删除自定义新拟态双向投影、左上高光及内描边。Card、Sidebar 选中项和 Overlay 使用库自带阴影，深色卡片不加投影。保留必要的独立 Card 边界，不通过增加阴影强度区分区域。

深色模式统一使用中性黑灰表面和浅蓝强调色。显式浅色、深色与跟随系统共用 `light-dark()` token，减少主题之间的漂移。

CSS 层顺序为 `theme → base → components → pro → app → utilities`。Pro 安装包包含预编译样式；独立层保证它能正确扩展基础组件，同时允许应用的布局与 Tailwind 工具类按预期生效。

## 安装与构建

按用户指定方式使用 `heroui-setup`，当前固定 1.0.4；`@heroui-pro/react` 固定 1.0.0-beta.11。`pnpm ui:setup` 从 `HEROUI_KEY` 环境变量读取访问码，以 CI 模式运行安装器，避免生成含明文访问码的 Vercel 配置。

- 本地：`pnpm install --frozen-lockfile`，然后 `pnpm ui:setup`。
- GitHub Actions：通过仓库 Secret `HEROUI_KEY` 提供构建凭据。
- Docker / Compose：通过 BuildKit secret 提供凭据；运行镜像不需要该变量。
- 公开 npm 包只是引导包。构建前检查真实组件与 CSS 是否存在；缺失时给出明确的安装指令。
