# Rubidium v2.0.0-alpha

This prerelease builds on the [backend review](backend-review.md) and deliberately
removes v1 compatibility. Install it with a fresh data directory or volume. Keep
your v1 instance, image and data separately; there is no v1 migration or restore
path in this release.

## Breaking changes

- Runtime storage is `rubidium.sqlite`, schema 6. Schema 0–5 databases with data,
  legacy `barker.sqlite` files and plaintext `access-password.txt` bootstrap files
  are rejected before initialization. Existing v1 data is not converted.
- Browser exports use envelope version 2 and schema 6. Operations backups use
  manifest format 2 and the `RUBIDIUM-OPS-BACKUP-2` encrypted header. V1 exports
  and backups cannot be imported or restored with v2.
- Only `RUBIDIUM_*` configuration names are supported. Remove `BARKER_*`
  variables, including empty aliases, and configure their current equivalents.
- Sessions use `rubidium_session`. V1 cookies are not accepted; sign in again.
- `/api/devices` and `/api/settings/test` are removed. Use `/api/channels` and
  `/api/channels/{id}/test` for Bark and Ntfy credentials and delivery tests.
- General settings contain preferences only: `displayTimeZone`,
  `historyRetentionDays`, `title`, `sound`, `group` and `icon`. Legacy credential
  fields are rejected. Channel revisions and preference revisions are independent.
- A real default channel row is required. Task `deviceId` remains the channel ID.
  Browser appearance preferences and unsaved-navigation markers use new v2 keys.
- Source Compose uses the new `rubidium-v2-data` volume instead of `barker-data`.
  Local source runs also need a fresh `RUBIDIUM_DATA_DIR` if `./data` contains v1.

## Delivery and reliability

The backend review fixes remain included: bounded provider acknowledgements,
durable delivery claims and retries, strict encrypted-import validation, password
reset and credential protections, and indexed history and queue operations.
See the review report for measured performance and verification limits.

The alpha contract may change before stable v2. Back up v2 data before replacing
an alpha build. This prerelease publishes the explicit `2.0.0-alpha` image tag
and its immutable source tag; it does not move `latest` or stable minor tags.
