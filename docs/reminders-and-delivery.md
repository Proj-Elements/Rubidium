# 提醒与投递

## 时间与重复

- 每条提醒都使用有效的 IANA 时区。开始时间是最早允许执行的那一分钟；新建提醒时已经过去的排期不会补发。
- 每月重复按相同的日历日算；当月不存在的 29–31 日直接跳过。
- 重复次数统计的是累计排期，包括已入队、已取消和已过期的时刻；发送失败后的重试不额外消耗次数。截止日期包含当天。
- 服务停机期间，没被暂停的任务会在恢复后补排；你自己暂停的那段时间不会补发。编辑、暂停、归档和删除之前，已到期的排期会先保存下来。
- 结束记录的自动保留默认是关的。开启后只会清理超期且已结束的投递记录，待投递、重试中和发送中的消息不受影响，任务累计次数也不会变。

## 投递状态

消息发送失败、网络超时、上游返回无效响应或服务不可用时，会被保留下来自动重试；上游给了 `Retry-After` 的话，重试时间会据此调整。在投递记录页可以查看尝试历史、手动重试，或者取消还在等待的投递。

投递采用至少一次语义：如果 Bark 已经收到请求、但确认响应丢了，后面的重试就可能造成重复通知。状态 `sent` 只代表 Bark API 确认收到，不保证设备上真的显示了通知。正在发送的请求可能已经被上游收下，撤不回来。

标题和正文加起来最多 3000 个 UTF-8 字节。配了 Ntfy 渠道的话，消息会发到所选主题；Bark 和 Ntfy 的连接状态可以在通知渠道设置里分别测试。
