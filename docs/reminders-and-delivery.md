# 提醒与投递

## 时间与重复

- 每条提醒使用有效 IANA 时区。开始时间是最早允许执行的分钟；新建时已过去的排期不会补发。
- 每月重复使用相同日历日；当月不存在的 29–31 日会跳过。
- 重复次数统计累计排期，包含已入队、已取消和已过期的时刻；发送失败重试不会额外消耗次数。截止日期包含当天。
- 服务停机时，未暂停任务会在恢复后补排；用户主动暂停期间不会补发。编辑、暂停、归档和删除前会先保存已到期的排期。
- 结束记录自动保留默认关闭；开启后只清理超期且已结束的投递记录，不影响待投递、重试中或发送中的消息，也不更改任务累计次数。

## 投递状态

消息在发送失败、网络超时、无效响应或服务不可用时会保留并自动重试；上游提供的 `Retry-After` 会用于调整重试时间。投递记录页可查看尝试历史、手动重试，或取消仍在等待的投递。

投递采用至少一次语义：如果 Bark 已接收请求但确认响应丢失，后续重试可能造成重复通知。状态 `sent` 表示 Bark API 已确认接收，不保证设备已显示通知。发送中的请求可能已被上游接收，无法撤回。

标题与正文总计最多 3000 个 UTF-8 字节。配置 Ntfy 渠道时，消息发送到所选主题；Bark 与 Ntfy 的连接状态可在通知渠道设置中分别测试。
